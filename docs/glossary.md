# Glossary

| Term                | Meaning                                                                                                                                                                                         |
| ------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Memory              | A durable, inspectable fact, preference, instruction or other useful piece of context. Chat messages are not automatically memories.                                                            |
| Vault               | One user's memories, policies, sources, suggestions and audit history.                                                                                                                          |
| Memory kind         | `FACT`, `PREFERENCE`, `INSTRUCTION`, `GOAL`, `PROJECT_CONTEXT`, `RELATIONSHIP`, `CONSTRAINT`, `EVENT` or `SUMMARY`; describes the content's role.                                               |
| Sensitivity         | Ordered labels `PUBLIC`, `LOW`, `INTERNAL`, `SENSITIVE`, `RESTRICTED`, `SECRET`. Policies impose a ceiling; labels do not encrypt content. Secret-like credentials are rejected before storage. |
| Memory bundle       | A bounded set of memory text selected for a particular client's task.                                                                                                                           |
| Client              | A registered AI tool or integration with an owner, trust level, declared retention and credentials.                                                                                             |
| Client grant        | Approval of a client together with its allowed scopes and app permissions; OAuth consent creates this grant.                                                                                    |
| First-party client  | A client representing Funes chat or voice. Its tool calls use the same policy and audit path as integrations.                                                                                   |
| Policy              | A client's rules for categories, sensitivity, operations, expiry and confirmation.                                                                                                              |
| Purpose             | Optional caller-declared audit reason. It never selects permissions or affects retrieval. Omitted, null or blank values persist as null.                                                        |
| Operation           | A policy permission: `READ`, `WRITE`, `SUGGEST`, `SUMMARIZE` or `EXPORT`.                                                                                                                       |
| Disclosure          | Memory text leaving the vault for a client or provider. Revocation prevents future access; it cannot erase a recipient's copy.                                                                  |
| Sharing request     | The owner's preview of an approval-gated request, with exact text, selected-memory approval or denial. Approval applies to that request once.                                                   |
| Suggestion          | A proposed memory or consolidation action awaiting policy or owner review.                                                                                                                      |
| Suggestion inbox    | The review queue at `/inbox`, including individual and bulk apply/reject controls.                                                                                                              |
| Quick capture       | Text queued from the web/PWA or a shortcut. It always becomes a reviewable suggestion after synchronization.                                                                                    |
| Provenance          | The append-only history explaining a memory's origin and changes.                                                                                                                               |
| Provenance subject  | A typed link from a provenance entry to a related memory, suggestion, job, request, client or other record.                                                                                     |
| Audit event         | An operational record of disclosure, authorization or a significant change. It avoids copies of memory bodies and credentials.                                                                  |
| Audit subject       | A typed, owner-scoped link from an audit event to an affected record.                                                                                                                           |
| Memory steward      | The chat tool orchestration that retrieves context, proposes edits and reports authoritative extraction results. It cannot override API policy checks.                                          |
| Extraction          | Finding durable claims in a conversation, checking them, and applying or queuing them under policy.                                                                                             |
| Consolidation       | Reviewing related saved memories for duplicates, conflicts, supersession and explicit expiry. It does not forget memories merely because they are old.                                          |
| Processing consent  | Versioned permission for a processor and task, separate from an external client's disclosure policy.                                                                                            |
| System 1            | The `system_1` configuration name for the classifier-led processing pipeline. The name evokes fast judgment; it is not a measured latency promise.                                              |
| System 2            | The `system_2` configuration name for the OpenAI LLM processing pipeline. The name evokes deliberate reasoning; it is not a quality guarantee.                                                  |
| Classifier provider | TypeSafe's Jev model, used to select and independently check candidate memories in System 1. Extraction also uses OpenAI to normalize selected passages.                                        |
| Noul probabilities  | The classifier SDK's probability outputs for candidate labels. Application thresholds interpret them as evidence, not certainty or authorization.                                               |
| Signals             | The UI design vocabulary: aggregate activity, restrained colors, labeled dots and readable prose. It is not an additional service or analytics collector.                                       |
| MCP                 | Model Context Protocol; the integration package exposes memory tools over stdio or Streamable HTTP.                                                                                             |
| PWA                 | An installable web application. Funes caches its shell and an explicit device-local capture queue, not API responses.                                                                           |
| Self-hosted         | The operator runs the vault on infrastructure they control. The server can read the data.                                                                                                       |
| Hosted              | A deployment run for users by another operator. Managed SaaS features are outside this release.                                                                                                 |
| Embedding           | A provider-generated numerical representation used for semantic retrieval; stored in pgvector with 1,536 dimensions.                                                                            |
| Job run             | Durable progress and outcome for asynchronous embedding or consolidation work. Redis/BullMQ schedules execution.                                                                                |
| Module              | A NestJS dependency boundary; see the [module map](../ARCHITECTURE.md#api-module-map) for each module's responsibility.                                                                         |
