# 0027 — Web Smoke Tests Run The Built App In CI

Date: 2026-07-09

Status: superseded

Superseded by: [0043](0043-isolated-google-browser-tests.md).

## Context and problem

The pipeline already built the workspace before E2E, but Playwright was starting `nest start --watch` and `next dev`, recompiling the app and exercising development-mode behavior. The smoke suite also depends on the demo-login control, and `NEXT_PUBLIC_DEMO_LOGIN` is inlined at Next build time.

## Decision outcome

CI runs the root Playwright web smoke suite against the production artifacts generated by the preceding `pnpm build` step. The API starts from `apps/api/dist/main.js`, and the web app starts with `next start` on the configured Playwright port. Local Playwright runs keep using dev servers, with `reuseExistingServer` enabled, so contributors can run the suite against an already-running stack.

## Consequences

The CI build step sets `NEXT_PUBLIC_DEMO_LOGIN=true` for this validation artifact only. If CI later publishes release images from the same job, the E2E build must be split from the release build so demo login is not accidentally shipped. The web smoke step should start faster and align with the compiled output the build step validated.
